## Independent review follow-up #38 — private outcomes in browser storage and cache

The final independent review found that an organizer's saved result drafts used a shared tournament/round key and public Pairings read them as fallback when the backend correctly redacted winner fields. Two regressions reproduced this for team and solo matches. Results draft hydration had the same missing editor boundary. A second source path was verified with four failing hook tests: the five-minute SWR cache reused organizer match payloads after switching to a participant or guest through client-side authentication.

The fix gives editor drafts a principal-specific key, omits that key for non-editors, gates Pairings/Results storage access on edit authority, and remounts their local state when viewer or authority changes. Logout removes only strictly recognized result-draft keys, including the legacy unscoped format, while preserving locale and unrelated storage. Legacy drafts cannot be assigned to an account reliably and are not migrated; new scoped drafts still survive the same editor's reloads. Both single-round and aggregate-round match hooks now wait for resolved authentication and use viewer-specific cache keys; their bound mutation interfaces and namespace remain intact.

Regression coverage includes null server outcomes with seeded private storage, account-specific keys, editor draft persistence, public Results hydration, narrowly scoped logout cleanup, and fresh redacted match requests after participant/guest switching. The original public server-published outcome tests remain passing. No standalone round-detail hook exists; the round/round-group hooks return metadata, not nested match payloads.

After the fix, 6 focused suites / 168 tests passed. Standalone TypeScript and diff checks passed. Owned-file lint passed with only the existing unused leaderboard parameter warning in `hooks/use-api.ts`.
